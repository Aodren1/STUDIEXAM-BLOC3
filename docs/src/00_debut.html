Synthèse

AbAssurance (12 millions de clients, Data Warehouse Oracle) a racheté AssurePlus (5 millions de clients, SQL Server). Les Blocs 1 et 2 ont spécifié puis piloté la plateforme qui doit unifier les deux systèmes d’information. Ce Bloc 3 la développe : un dépôt Python public, un modèle de données unifié, un pipeline réel et un tableau de bord qui donne, pour validation du projet, les statistiques des deux bases.

Le dépôt suit un Git Flow simplifié (main, develop, branches feature/, fix/, ci/, docs/, release/), avec une convention de nommage <type>/FUS-<n>-<description> vérifiée automatiquement. Le modèle final (onze entités) sépare le compte client tel qu’il existe dans chaque source de la personne réelle obtenue après dédoublonnage. Cette distinction conditionne toutes les statistiques consolidées.

Le pipeline reproduit la chaîne retenue au Bloc 1 : extraction (rôle Talend) des huit tables, publication sur huit topics Kafka, puis trois traitements (silver, doublons, gold) écrits deux fois, en Python pour le poste et le serveur de démonstration, en PySpark pour le cluster. Les deux versions appliquent le même mapping déclaratif et les mêmes règles, et la CI vérifie qu’elles produisent les mêmes chiffres. Les données nettoyées vont dans un lac à trois zones (local ou HDFS via WebHDFS) et dans un entrepôt dont les clés étrangères appliquent le MCD. Un orphelin n’est jamais supprimé : il est mis en quarantaine avec son motif.

La qualité est contrôlée par ruff, bandit et SonarCloud dans la CI : des 149 alertes ruff et 7 bandit du premier passage, il n’en reste aucune, et les alertes d’injection SQL ont été corrigées par une liste blanche, pas masquées. Les tests locaux (plus six tests Spark et Kafka en CI) couvrent des lignes. Enfin, le bug du dossier 3 a été réellement rencontré : sans donnée nouvelle, une seconde exécution doublait toutes les tables silver. Le contrôle de réconciliation a bloqué la publication ; le défaut a été reproduit par cinq tests, puis corrigé et validé.
